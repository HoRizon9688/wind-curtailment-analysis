## 5. T2 必须先处理的缺陷

### 日期转换（2 个单元格）

1900 活动工作表及 1904 日期样例的 00:15 日期单元格：Python 为 `2026-08-01T00:15:00`，当前 JS 为 `2026-08-01T00:14:59.999Z`（UTC 编码墙钟 Date）。这是整数分钟被误读，不是两者实际相差时区。

根因已从锁定依赖源码确认：`read-excel-file@9.3.10/modules/xlsx/parseExcelTimestamp.js` 使用 Math.floor；openpyxl `from_excel` 对日小数舍入到毫秒。不能统一对最终 Date 取整到分钟，否则会掩盖真实非零秒。T2 必须在保留原始日期序列语义的基础上适配，同时测试真实秒/毫秒仍被拒绝，支持两个日期系统。公开读取选项没有日期解析回调；具体实现要复审，禁止直接改 node_modules 或引入按文件名绕过的白名单。

### 数字转换（4 个输入）

Python 对 `+1.5`、`1_000`、全角 `１２`、阿拉伯数字 `١٢` 的结果分别为 1.5、1000、12、12；当前 numberOrNull 都返回 null。已保存 numbers.json，T2 应迁移 Python 的有限数字转换语义，继续拒绝布尔、空值、NaN 和 Infinity。

审计证据位于本机 `reports/browser-review/T1/table-audit.json`（gitignored，全部为合成数据）；仓库脚本可重新生成同样的差异报告。日期例子使用固定 Python 期望，没有通过改期望或扩大容差消除差异。
