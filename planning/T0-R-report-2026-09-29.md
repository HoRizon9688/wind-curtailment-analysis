### 2.1 第二项基线缺陷（本轮新发现，必须处理才能满足「全新检出可校验」）

完整校验此前**停在缺失的 hosting.json**，因此第二处不到位一直没暴露。修复后立刻发现：

```text
Protected Data app runtime file was modified: index.html
```

根因：`protected-runtime.json` 按**工作区字节**计算摘要，而本机 `core.autocrlf=true`，
Windows 检出把受保护文本文件写成 CRLF。仓库原有 `*.py/*.mjs/*.jsx/*.json/*.md/*.css`
已显式 `eol=lf`，唯独 `.html` 缺失，且 `dashboard/` 树没有整体覆盖。

同一文件两种字节的实测摘要：

```text
LF   （git blob） 314bb3975bdcd7322067d234f99398b06f609c67c2321554eda742f2338b3c5e  ← 清单值
CRLF （工作区）   48bb557e34d552e03a277556e5e13872b68050f5e50375ad29c1b018aecea97d
```

修复（`.gitattributes`，仓库根、非受保护文件）：新增

```gitattributes
*.html text eol=lf
dashboard/** text=auto eol=lf
```

随后重建受保护工作区字节，完整校验**首次通过**。

### 3.1 longtask 结论确实被推翻

修正后实测（HeadlessChrome，31 天，3,526,598 字节 / 44,641 行）：


### 4.2 职责划分（不维护两份业务解释）

- `read-excel-file`（`/universal` 入口，Node 与浏览器同一份 import）：单元格取值、共享/内联字符串、缓存公式、日期与日期系统。
- `fflate`：工作簿元数据（`activeTab`、工作表顺序、`date1904`）与**实际**展开上限。前者是元数据提取，不是第二套单元格解析。
- 适配层（`dashboard/src/content/calculation/table-reader.mjs`）：严格 CSV 解码、原始字节哈希、60 MB 输入闸、表头规则、工作表选择策略。
- 自研 ZIP/XML 解析器**已删除**，不再存在两条解释。

### 4.3 工作表选择已按基线修正

### 4.5 库无法覆盖、由适配层补齐的项

- **CSV 严格编码 / 哈希 / 表头 / 字节限额**：库不涉及，仍在适配层。

## 7. 已知限制与需协调者决定

1. **本机同步子进程被环境阻断。** `child_process.spawnSync` / `execFileSync` 在本机任何
   Node（22/24）、任何宿主（Bash/PowerShell）、任何 `NODE_OPTIONS` 配置下均立即返回 `EBUSY`，
   而异步 `spawn` 正常。Data 插件通过 `runDataNode()` 以 `spawnSync` 调用 Vite，故无法直接运行。
   为完成核定的「真实构建」要求，提供了 `tests/browser/sync-spawn-bridge.cjs`：
   以 `NODE_OPTIONS=--require` 预加载，把同步入口换成基于异步 `spawn` + Worker 线程 + 共享内存的等价实现。
   **它不修改插件**，且仅在构建/验证命令中启用。协调者环境既有可用的 `spawnSync`，
   请在原生环境复跑 §6.2 以确认；若视桥接为不可接受，请裁定替代验证方式。
2. **`/api/health` 遗留探测。** 现有作者内容 `UploadPanel` 仍在上挂载时探测 `/api/health`，
   静态构建下必然 404（本轮已作为**唯一的**预期控制台错误单列：`legacyHealthProbe: true`）。
   规范 §1/§7 明确浏览器模式不得依赖该接口，须在 **T5** 移除；本轮未改 UX。
3. **空中间单元格的共享风险（新发现）。** `gaps.xlsx` 对照显示 **openpyxl 与 read-excel-file
   都会把缺列行压缩**（`['a1','c1']` 而非按列引用对齐），因此含空中间列的表格在
   `dict(zip(headers,row))` 下会把后列值映射到前面的表头。这是**基线既有**行为，
   不是本轮引入；两条路径目前一致，故 G1 的逐分钟一致性不受影响。
   建议 **T1 在契约层显式定义空单元格语义**并决定是否按列引用定位，不应单方面改 Python。
4. **Worker 决策**：31 天实测存在约 145 ms 长任务，366 天与 T3 真实算法未测；留待 T4。
5. **未运行**：366 天边界性能、T3 真实算法的性能与取消、真实数据私有对照（属审核 R 与 T3/T4 阶段）。
   发布与 T1 均未执行。
