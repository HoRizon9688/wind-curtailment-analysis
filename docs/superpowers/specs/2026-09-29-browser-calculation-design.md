日期：2026-09-29。基线：`26fd0e7ff436f92327063140f5352cd9b6466327`。
状态：供交接执行的设计；T0 技术验证和分阶段审核尚未执行。

## 1. 范围与架构

目标是静态站点直接选择本地文件并生成计算结果。以 JavaScript ES Modules 迁移当前 Python 计算路径，保留 Python 作为基线与本机功能。React/CSS/SVG 展示沿用现有页面。文件读取、运算和哈希在浏览器完成，默认不持久化上传内容。

```mermaid
flowchart LR
  A[用户选择分钟表与预测表] --> B[校验容量 日期 文件数量与大小]
  B --> C[浏览器计算任务]
  C --> D[文件解析 时间匹配 线性插值]
  D --> E[按分钟推进阈值状态与限电分解]
  E --> F[逐分钟结果 汇总 缺失区间 来源]
  F --> G[完整成功后一次性替换当前分析]
  G --> H[图表 来源查看 CSV与JSON导出]
```

Python 和 Node 可以用于开发、生成对照样例及构建；线上访问者计算时不能依赖它们，也不能调用 `/api/health` 或 `/api/calculate`。保留原本机模式须显式分支，不允许静默回退上传。

首版不包含：云端存储、用户账号、自动历史恢复、跨场站合并、储能归因、调整阈值的新 UI、自动填补缺失值、总指令限电校核面板。内部校核字段必须保留给测试和审查。

## 3. 输入契约

分钟表必需列：`时间`、`可用功率`、`全站总有功_集电线有功之和`、`AGC有功设定值`；`理论功率`可选。

预测表必需列：`预测id`、`名称`、`预测时间`、`考核点2预测结果`。只读取第二点，不使用平均预测结果替代。每次只允许一个预测场站。分钟表没有场站标识，不能假装自动证明它与预测表同站，界面须提醒用户确认。

- 格式：UTF-8（含 BOM）或 GB18030 CSV；XLSX；扩展名为 XLS 的 OOXML ZIP。旧二进制 XLS 延续现有报错，要求另存为 XLSX；不擅自扩大格式范围。
- CSV：正确处理引号、逗号、换行、空单元格；先严格 UTF-8 解码，失败再 GB18030，不能用替换字符静默吞掉编码错误。
- Excel：优先工作表 `功率预测`，不存在时选工作簿 active 工作表；验证日期单元格、1900/1904 日期系统和公式缓存值。没有公式缓存值视为缺值，不自行计算 Excel 公式。
- 按内容识别 OOXML，不能仅凭扩展名猜测。解析前检查总输入大小，解压时检查展开大小，单工作簿展开上限延续 150,000,000 字节，不应先无限解压再检查。
- 文件总大小上限 60,000,000 字节，每类 1～400 个文件；空文件拒绝；容量必须是有限正数，不能接受 NaN/Infinity。
- 计算范围连续 1～366 天。浏览器内存实测可能促成另行批准的范围收缩，但不能悄悄截断数据或只算前 N 行。
- 空白行忽略；表头去除首尾空白；缺列或非空重名列报错。重复且数值一致去重；冲突报错，不平均、不按“最后文件”覆盖。理论功率在重复比较范围内，延续基线行为。
- 预测空值行按基线计数跳过；错误需指出文件、行号或字段，区别可排除分钟与整份输入无法解析。遇到不支持的日期必须报错，不能自动换成本机时间。

## 4. 时间规则

统一固定 UTC+08:00，与浏览器操作系统时区无关。内部可用整数 epoch 毫秒；不得用未明确时区的 `new Date(中文日期文本)` 隐式解析。

无时区文本按 UTC+08:00；带偏移的文本换算到 UTC+08:00；分钟数据若秒/微秒非零，拒绝而不是取整。接受现有解析器已支持的 ISO 与年月日斜杠/横杠常见形式，尤其 `2026/8/1 0:00`。

预测表的“预测时间”是版本时刻，第二点目标为版本 +15 分钟，不是上传时间再加 15 分钟。例如：23:45 上传 → 00:00 版本 → 00:15 第二点生效。预测版本须对齐 15 分钟。

相邻目标恰隔 15 分钟时，`F(t)=F左+(F右−F左)*(t−t左)/900000`。精确节点独立有效；不外推、不跨缺失节点插值。两端值都必须在 `[0,C]`，不能因插值值落在范围内就忽略坏端点。

每条分钟记录代表 `[t,t+1分钟)`。推定日期时，末尾额外的次日 00:00 不形成新一天。用户起止日期均包含整日，生成每日报告 1440 行；原始分钟缺行保留为排除行。

计算从所选起始日零点以关闭状态开始，跨日延续状态；排除分钟重置状态。改变日期选择后必须重算，不能直接截取另一长区间的结果冒充同一个独立计算。图表内筛选不重算，只汇总当前已计算行。

## 5. 分类规则冻结

容量 C，可用 A，线性插值预测 F，AGC G，实发 P，均为 MW。所有输入须先通过有效分钟判定。

| 项目 | 当前规则 |
|---|---|
| AGC 下限跟随参考 | `max(F,0.02*C)`；不改写 F/G，不据此增加调度限电 |
| 调度状态进入 | `F-G > 0.01*C` |
| 调度状态保持 | 已进入且 `F-G > 0.005*C`，否则退出 |
| 跟随成立 | 非调度状态，且 `abs(G-max(F,0.02*C)) <= 0.01*C` |
| 预测状态进入 | `A-max(F,G) > 0.02*C` |
| 预测状态保持 | 已进入且 `A-max(F,G) > 0.01*C`；若既不跟随又不调度，强制退出 |
| 指令以下场站未发 | `max(min(A,G)-P,0) > 0.005*C`，否则为指令以下小偏差 |

严格保留 `>` 与 `<=` 边界。不能通过“改为大于等于”或加入 epsilon 来改变分类。阈值用于判定状态，不从分类电量中扣除一段阈值功率。不增加最短持续时间或移动平均。

先计算功率：

```text
bottom = max(G,P)
U = max(A-bottom,0)
D = 调度状态 ? max(min(A,F)-bottom,0) : 0
R = 预测状态 ? (调度状态 ? max(A-max(F,G,P),0) : U) : 0
remaining = max(U-D-R,0)
B = max(min(A,G)-P,0)
other = remaining+B
unexplainedAbove = 既不跟随又不调度 ? remaining : 0
noiseAbove = remaining-unexplainedAbove
operationalBelow = B > 0.005*C ? B : 0
noiseBelow = B-operationalBelow
gap = max(A-P,0)
referenceTotal = max(A-G,0)
releasedAboveAgc = max(min(A,P)-G,0)
```

D 对应 `dispatch`，R 对应 `prediction`。以上所有功率差对应的结果字段除以 60 后为每分钟 MWh；`a/p/g/f/theory/trackingReference` 和 `allocationBands.bottom/top` 始终是 MW。面积边界须复现 Python `allocationBands`，不以曲线是否显示影响计算。

验收必须验证两个恒等式（逐分钟及累计）：

```text
gap = dispatch + prediction + other
referenceTotal = dispatch + prediction + noiseAbove + unexplainedAbove + releasedAboveAgc
```

第二个式子的剩余项不得强行塞入两类限电。总指令限电校核继续只保留在审计结果中，不增加到网页指标。

## 6. 排除与统计

排除条件逐项移植 `analyze_uploads`：分钟缺行/缺值、负实发、预测缺失、预测端点越界、A/G/F 负值、A/P/G/F 超容量。负实发是低风厂用电，整分钟排除，不改成零。

`P>A` 且其他条件有效时，保留有效分钟，标记基准异常，正差额为零。不要把它改成整分钟排除。理论功率不是计算基准，其缺失不排除。

排除行分类电量为 null，不是 0；原始能读出的功率保留。多原因可重叠，整期 excluded 按唯一分钟去重；每种原因区间采用 `[start,end)`，不能累加各原因分钟当总排除分钟。

沿用结果对象的 `meta/summary/daily/gaps/rows/calibration`。参与和排除计数、状态布尔值、时间、文件 SHA-256、来源行、左右节点/版本/权重均可追溯。展示层不提供校核面板；开发测试保留 calibration。零有效分钟不能显示“0 MWh，计算正常”，应显示无有效结果及原因。两类限电总和为零时占比为 null。

## 7. 页面与数据生命周期

上传表单有独立“草稿参数”；成功结果有固定“已计算参数”。更改表单容量不能即时改动旧结果的场站标签。开始处理新数据时，旧结果隐藏或明确显示为“上一次成功分析”，禁用可能误导的来源/导出操作；失败后恢复旧分析和原参数，显示失败原因。

任务分配唯一 requestId。取消时终止 Worker；晚到结果必须忽略。成功时一次替换 rows、meta、summary、daily、gaps 和来源元数据；日期选择重置至新结果第一天，分钟范围/分页/回放状态重置。不得把新行和旧总数混用。

保留曲线/阴影独立开关、拖选缩放、分钟查看、日选择、深浅色和键盘操作。分类面积来自同一套结果。新增整期日汇总、排除区间、当前范围/整期明细以及完整结果 JSON 下载；使用 UTF-8 BOM CSV、正确转义及公式注入文本保护。来源哈希对应原始文件字节，不是解码后的字符串。

不把上传内容、文件名、站名、哈希、计算结果发到远端接口、遥测、发布服务或公开快照。不自动写入 localStorage/IndexedDB，不增加 Service Worker 持久缓存业务数据；保留主题/布局偏好不等同于允许存储数据。必须审查现有壳层的自动保存、来源和导出路径。允许正常请求程序、Worker 和合成示例资源。

## 8. 性能与构建要求

先测量再引入 Worker，T0 记录解析/计算是否阻塞主线程，按 `dashboard/AGENTS.md` 使用受支持的 Worker 构建形式。大批量解析与顺序运算应放在同一后台任务，减少内存复制。不要把有状态算法任意按天并行。

必测 15 天、31 天以及 366 天合成输入；记录文件字节、行数、浏览器版本、CPU/内存、冷/热启动、读取/计算/渲染耗时和可测内存指标。31 天交互过程中取消应在 1 秒内得到 UI 确认，不允许一次同步任务造成超过 1 秒的界面失去响应；对结果渲染也测量，不能只测 Worker。性能目标不是当前已经测得的结论。

366 天属于边界能力验证，若无法安全支持，必须报告并提交明确的范围调整建议，经协调核定后更新说明与测试；不得虚假保留 366 天承诺。所有未运行的浏览器检查必须注明。

公共静态包仅含程序与合成数据，所有资源支持 `/wind-curtailment-analysis/` 子路径。保留现有合成演示可打开。线上计算路径不因 `/api` 不存在而禁用。修改构建路径时保持本机私有快照不变，禁止复制真实 `reports/latest` 或 `dashboard/src/data.json` 到公共包。

受保护运行时的必要改动先在 T0 写入准确路径清单，遵守其范围授权与源码构建要求。不能建立伪造 Provider、覆盖全局 DOM 或关闭保护来绕过接口。若未能建立合法动态快照接入，就视为 G0 未通过，而不是交付来源不一致的半成品。
